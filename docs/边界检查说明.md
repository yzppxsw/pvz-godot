# 种植边界的数组越界问题

> 记录时间:2026-10-20
> 相关文件:`Scripts/map/map.gd`
> 状态:待深入研究

---

## 一、问题现象

在草坪上种植植物时,如果鼠标点在草坪的最右边缘或最下边缘,可能出现:

- 报错:`Index p_index = 9 is out of bounds (size = 9)`
- 或者更隐蔽:植物莫名其妙种到了**最右边一列**,而不是点击的位置

---

## 二、相关代码

### 坐标换算(`_on_lawn_input`)

```gdscript
var size := (Lawn.shape as RectangleShape2D).size          # 草坪矩形尺寸
var local := Lawn.get_local_mouse_position() + size / 2.0  # 转成以左上角为原点
var col := int(local.x / (size.x / Cols))                  # 第几列
var row := int(local.y / (size.y / Rows))                  # 第几行
```

### 使用索引(`plant_landed`)

```gdscript
func plant_landed(cell_pos, cell_size, x, y, row, col):
	if Gamedata.holding_plant and Gamedata.plant_grid[row][col] == 0:
		...
```

---

## 三、为什么 Area2D 的区域检测不够

`Lawn` 是 Area2D,`input_event` 只在鼠标位于**碰撞形状内部**时触发。但这只保证了:

```
鼠标在形状内     ≠     算出来的行列索引合法
```

两者是不同的事情。

---

## 四、四种越界原因

### 1. 边界点本身就越界(主因,与精度无关)

假设 `Cols = 9`,草坪宽 `729`,每格宽 `81`:

```
x 位置:   0    81   162  ...  648   729
col:      0     1     2  ...    8     9   ← 越界
```

形状范围是**闭区间** `[0, 729]`,`729` 这个点在形状内是合法的;但按格子划分,它对应第 10 个格子(索引 9),而数组只有索引 0~8。

这是一个**必然的 off-by-one**,不是计算错误。

### 2. 浮点精度抖动

```gdscript
int(728.9999 / 81) = 8    # 正常
int(729.0001 / 81) = 9    # 越界
```

边界附近的浮点误差会让结果在合法/非法之间跳变。

### 3. 负数索引静默环绕(最隐蔽)

如果因坐标换算偏差出现 `col = -1`:

```gdscript
plant_grid[row][-1]
```

GDScript 里**负数索引不会报错**,而是取**最后一个元素**。于是植物会被种到最右边一列,表面上"程序没崩",实际是错误行为。

### 4. 碰撞形状与网格尺寸不同步

如果以后在编辑器里调整了 `Lawn` 的碰撞矩形(比如放大草坪),`size` 会变,但 `Rows / Cols` 没变,索引就可能超出范围。

---

## 五、修复方法

在算完 `row` / `col` 之后、调用 `plant_landed` 之前,加一道边界判断:

```gdscript
if row < 0 or row >= Rows or col < 0 or col >= Cols:
	return
```

含义:

| 条件 | 含义 |
|---|---|
| `row < 0` | 鼠标在草坪上方之外 |
| `row >= Rows` | 鼠标在草坪下方之外 |
| `col < 0` | 鼠标在草坪左侧之外 |
| `col >= Cols` | 鼠标在草坪右侧之外 |

`return` 会立刻结束 `_on_lawn_input`,这次点击作废。

**位置要求**:必须在 `plant_landed` 之前,因为 `plant_landed` 第一句就访问 `plant_grid[row][col]`。

---

## 六、如何验证

临时打印索引,然后贴着草坪最右/最下边缘点击:

```gdscript
print("row=", row, " col=", col, " Rows=", Rows, " Cols=", Cols)
```

如果出现 `col == Cols` 或 `row == Rows`,说明边界检查确实被触发。

也可以临时把检查改成:

```gdscript
if row < 0 or row >= Rows or col < 0 or col >= Cols:
	print("越界点击: row=", row, " col=", col)
	return
```

---

## 七、结论

这不是"修一个已经出现的 bug",而是**防御性编程**:

- 正常游玩时几乎不会触发
- 成本只有 4 行代码
- 能同时兜住:边界 off-by-one、浮点精度、负数索引静默环绕、未来改形状

## 八、可继续研究的方向

1. GDScript 的负数索引规则(为什么 `array[-1]` 合法)

3. 用 `clampi()` 把索引强制夹到合法范围,与直接 `return` 的取舍
4. 把"屏幕坐标 → 格子坐标"封装成一个统一函数,避免多处重复换算
